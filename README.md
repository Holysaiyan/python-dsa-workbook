# Python DSA Workbook

An interactive data structures and algorithms course in Python, built for graduate coding
assessments. Twenty-one lessons, each with runnable examples, a quiz, an auto-tested practice
problem, a planted bug to fix, a complexity gate and a rebuild-from-memory step. Python runs in
the browser; there is no server and no account.

**Live site:** https://holysaiyan.github.io/python-dsa-workbook/

## What is in a lesson

1. A short explanation with examples you can edit and run. Press **Predict** to write down what an
   example prints before running it.
2. **Check your understanding**: 4 to 7 questions with explanations.
3. **Practice**: a problem with visible and hidden tests, hints, a timer and a locked model
   solution. After the tests pass, you state the time and space complexity, then rebuild the
   solution from a blank editor.
4. **Fix the bug**: the same problem with a realistic bug in it.
5. A lesson is **mastered** when all of that is done. The **Mixed review** page draws ten quiz
   questions across lessons, wrong answers first, and lists what each lesson still needs.

## Repository layout

```
index.html              course home page (generated by src/home.py)
workbook/index.html     the workbook app (generated by src/assemble.py)
workbook/lessons.js     all lesson data (generated and verified by src/build.py)
workbook/vendor/        Brython 3.13.2 (BSD-3-Clause, see vendor/LICENSE)
src/m1.py ... m6.py     lesson content: explanations, examples, practice problems, tests
src/extras.py           quiz questions, bug-fix variants, complexity answers, time targets
src/build.py            runs and verifies everything, writes workbook/lessons.js
src/template.html       the app's HTML, CSS and JavaScript
src/runner.py           the in-browser Python runner (captures output, matches CPython's JSON errors)
src/assemble.py         combines template + runner into workbook/index.html
src/home.py             writes index.html from the lesson data
.github/workflows/      CI: rebuilds, fails if the generated files are out of date, deploys to Pages
```

## Build locally

Requires Python 3.11 or later and nothing else.

```bash
python3 src/build.py      # runs every example and test in CPython; fails on any mismatch
python3 src/assemble.py   # writes workbook/index.html
python3 src/home.py       # writes index.html
python3 -m http.server    # then open http://localhost:8000/
```

`build.py` refuses to write `lessons.js` if an example fails, a model solution fails its tests, a
starter accidentally passes, a buggy variant fails no visible test, or a quiz answer disagrees
with what the code prints. That is what keeps the published content correct.

## Add or change a lesson

Each lesson in `src/m*.py` is a dictionary: `blocks` (paragraphs, headings, code examples, tables,
steps, tips), `mistakes`, and a `practice` problem with `func`, `starter`, `tests` (label, args,
hidden), `hints`, `solution` and `explain`. Its quiz, bug-fix variant and complexity gate live in
`src/extras.py` under the same lesson id. Run the three build steps and open the page.

## Deployment

Every push to `main` runs `.github/workflows/ci.yml`. It rebuilds the lesson data in CPython, fails
if any example, test or quiz answer disagrees with the committed files, and then deploys the site
to GitHub Pages. Before the first deployment, open the repository's **Settings**, then **Pages**,
and set **Source** to **GitHub Actions** (a one-time step that only the repository owner can do).
The site is then served at `https://<your-username>.github.io/<repository-name>/`.
